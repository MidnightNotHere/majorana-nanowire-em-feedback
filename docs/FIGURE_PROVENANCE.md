The table was built from the tracked files by a static scan: the file name of every PNG was searched for in the `src/` and `scripts/` sources, byte copies were identified by SHA-256, and the "Generated by" text of each caption was parsed out of `paper/main.tex`. Files named in the tables were checked to exist. Run times come from [`REPRODUCING.md`](REPRODUCING.md).

## 2. Mismatches found

1. **Captions of Figs. 4, 5 and 8 named the module that writes the data, not the script that draws the figure.** `bdg_r5_physically_meaningful_shift.py` and `bdg_r9_multisubband_sweep.py` write only JSON files; the images are drawn by `scripts/redraw_paper_fig3.py` and `scripts/redraw_paper_fig6.py`; Fig. 5's image is a re-titled redraw, by `scripts/redraw_paper_fig4.py`, of the figure that `bdg_r9_pole_characterization.py` draws. **Corrected** on 2026-10-26: the captions now name the redraw script, the data file it reads and the module that writes it.
2. **Caption of Fig. 3 gave a data folder, but the R4 module saves no data file.** **Corrected** on 2026-10-26: the caption says the module saves only the figure.
3. **`docs/paper_audit/PAPER_SUMMARY_AND_VERIFICATION_LOG.md` numbered the figure files as the figures of the paper and named the wrong generators** for `fig3_null_validation.png` and `fig6_multisubband_summary.png`. The log keeps its original text and carries dated correction notes (2026-10-25), see `KNOWN_ISSUES.md`, section 2.
4. **Seven images had no script in the repository that could draw them from the saved data.** The plotting code of `r5_figure10_shift_vs_g.png`, `r5_figure11_headline_validation.png`, `r9_multisubband_summary.png` and of the paper's `fig3_null_validation.png` and `fig6_multisubband_summary.png` was in neither the repository nor its history; `r9_disorder_summary.png` (and the paper's copy of it) was drawn only at the end of the 4,627 s full run; and the paper's `fig4_bounded_pole.png` was made with an ad hoc script, `regen_fig3.py`, that was never committed. **Resolved:** each now has a script in `scripts/` that draws it from the committed data. The plotting code of the first five is a reconstruction fitted to the committed images, not the code that first made them (`KNOWN_ISSUES.md`, section 3).
5. **Still without a script:** `results/disorder/r9_disorder_summary.SUPERSEDED_task4_3.png`, the record of a superseded result (drawn by an earlier version of `make_figures()`). It is kept on purpose.
6. **Stale label, regeneration needed before the release:** `results/em_feedback_detector_comparison/r4_figure4_phase_shift_preview.png` still carries the title "R4 Figure 4" and the old `src/` path of its methods note. The code that draws it (`figure4_phase_shift_preview()` in `src/bdg_r4_em_coupling.py`) already has the corrected text, but recomputing it takes more than 45 minutes and was not done. The command to regenerate it is in `REPRODUCING.md`, section 4, and the item is listed under "regenerate before release" in `KNOWN_ISSUES.md`, section 3.
